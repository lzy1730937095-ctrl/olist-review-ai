# Olist 电商差评分析与 AI 分类

> **English summary.** Using 100k+ orders from Olist, a Brazilian e-commerce marketplace, I used SQL to show that late deliveries drive negative reviews: 62.4% of late orders get a 1–2 star review, versus 9.3% of on-time orders. I then designed an 8-category taxonomy for complaint reviews, hand-labelled a 100-review evaluation set (86% inter-annotator agreement), and compared a keyword baseline with an LLM classifier (DeepSeek). For the "not received / late" category, the LLM raised precision from 58.3% to 97.6% at 93.2% recall. Across all 8 categories it reached 93.2% micro-precision and 94.8% micro-recall, matching the gold labels exactly on 89 of 100 reviews.

## 1. 要回答的问题

1. 差评主要是由什么造成的？配送延迟的影响有多大？
2. 用户的差评到底在抱怨哪些具体问题？
3. 能不能用大模型自动给差评分类？比简单的关键词规则好多少？

## 2. 数据

- **来源：** [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)（Kaggle），2016–2018 年约 10 万笔订单
- **使用的表：** 订单、评价、用户
- **评论语言：** 葡萄牙语。数据集已做匿名处理，评论中的公司名被替换成了《权力的游戏》里的家族名（如 lannister、stark）
- 本仓库只包含 100 条抽样评论及其标注，原始数据请从 Kaggle 下载。数据使用条款以 Kaggle 页面为准

## 3. 方法

```
① SQL 分析 → ② 设计分类体系 → ③ 人工标注评估集 → ④ 关键词基准 vs 大模型 → ⑤ 错误分析
```

## 4. 结果

### 4.1 SQL 分析：配送延迟是差评的重要原因

只看已送达订单（96,353 笔有送达时间且有评价）：

| 配送情况 | 订单数 | 平均评分 | 差评率（1–2 分） |
|---|---|---|---|
| 准时 | 89,944 | 4.29 | 9.3% |
| 延迟 | 6,409 | 2.27 | **62.4%** |

**延迟订单的差评率约为准时订单的 7 倍。** 为了排除“相关不等于因果”的其他解释，又做了两项检验：

**剂量效应：延迟越久，评分越低**

| 延迟天数 | 订单数 | 平均评分 | 差评率 |
|---|---|---|---|
| 准时 | 89,944 | 4.29 | 9.3% |
| 1–3 天 | 1,856 | 3.29 | 32.2% |
| 4–7 天 | 1,756 | 2.10 | 67.7% |
| 8–14 天 | 1,452 | 1.68 | 80.0% |
| 15 天以上 | 1,345 | 1.72 | 78.3% |

**控制地区：** 订单量前 5 的州里，准时订单的平均分都在 4.24–4.32 之间，延迟订单都在 1.91–2.67 之间。差距在每个州都存在，说明不是“某些地区的用户本来就爱打低分”。

**其他发现：**
- 全部差评中 **85% 来自“已送达”订单**（12,347 条）。已送达订单平均分 4.16，看起来不错，但掩盖了大量差评
- 圣保罗州（SP）订单占 42%，前 3 个州约占 2/3
- **口径说明：** 预计送达时间只精确到日期（当天 00:00），如果直接比较时间戳，会有 1,292 笔当天送达的订单被误判为延迟，所以只比较日期部分

SQL 代码见 [`sql/delivery_vs_reviews.sql`](sql/delivery_vs_reviews.sql)。

### 4.2 分类体系与评估集

**为什么需要人工标注：** 没有标准答案，就无法衡量 AI 分类准不准。

- **抽样：** 从 10,890 条“差评且写了评论”的评价中随机抽取 100 条（`random_state=42`）。只从差评中抽样，是因为实际只会把差评交给 AI 分类，考卷要和实际使用的数据一致
- **分类体系：** 8 个类别，经过 4 个版本的迭代，详见 [`labeling_guide.md`](labeling_guide.md)
- **一致性检查：** 两名标注者独立标注后对比，五批一致率分别为 80% / 90% / 95% / 85% / 80%，**整体 86%**。每次出现分歧都补充规则，分歧样本按规范统一裁决
- **语言处理：** 标注者不懂葡萄牙语，借助机器翻译标注，并对存疑样本用第二个翻译工具交叉核对

**100 条差评的问题分布**（可多选，14 条涉及多个问题）：

| 类别 | 条数 |
|---|---|
| 1 未收到 / 送达延迟 | **44** |
| 2 少发 / 漏发 | 16 |
| 5 商品缺陷 | 15 |
| 7 客服 / 售后问题 | 12 |
| 3 发错货 | 11 |
| 4 与描述不符 | 8 |
| 8 其他 | 5 |
| 6 运输破损 / 包装问题 | 4 |

- 物流相关问题占比最高（44%），与 SQL 结论一致
- **“少发 + 发错货”合计 27%**，属于卖家发货环节的问题，与物流公司无关，只优化物流会漏掉这部分
- “其他”只占 5%，说明分类体系能覆盖绝大多数差评

### 4.3 关键词基准 vs 大模型

**“1 未收到 / 送达延迟”类别：**

| 方法 | 精确率 | 召回率 |
|---|---|---|
| 关键词 v1（7 个词根） | 58.3% | 79.5% |
| 关键词 v2（加入 entreg） | 57.5% | 95.5% |
| **DeepSeek + prompt v2** | **97.6%** | **93.2%** |

**关键词方法的问题：**
- **只认字母，不理解意思：**“Recebi o produto errado”（收到的是错的）因为含有“收到”被误判为未收到
- **词根碰巧出现在别的词里：**“che”匹配到了 cheiro（气味）、checou（检查）
- **加关键词只能用精确率换召回率：** 加入 entreg 后召回率升到 95.5%，但精确率反而下降
- **无法处理错别字、语序变化和没有关键词的表达**

**大模型在全部 8 个类别上的表现：**

| 类别 | 精确率 | 召回率 |
|---|---|---|
| 1 未收到 / 送达延迟 | 97.6% | 93.2% |
| 2 少发 / 漏发 | 94.1% | 100% |
| 3 发错货 | 91.7% | 100% |
| 4 与描述不符 | 100% | 87.5% |
| 5 商品缺陷 | 100% | 93.3% |
| 6 运输破损 / 包装 | 100% | 100% |
| 7 客服 / 售后 | 92.3% | 100% |
| 8 其他 | 50.0% | 80.0% |
| **合计（micro）** | **93.2%** | **94.8%** |

- **89 / 100 条与标准答案完全一致**（包括多标签），100 次调用全部返回合法 JSON
- 设置：模型 `deepseek-flash`，prompt 见 [`src/prompt_v2.txt`](src/prompt_v2.txt)，2026 年 10 月运行
- prompt 中的 6 条示例全部来自评估集以外的评论，避免数据泄露

### 4.4 错误分析

11 条不一致的样本分为三类：

| 原因 | 条数 | 例子 | 处理 |
|---|---|---|---|
| **prompt 缺少规则** | 3 | 用户提到“没收到发票”，AI 额外标了“其他” | v3 加规则：发票问题不单独标类别 |
| **多标签漏标** | 3 | “问了好几次配送情况都没人回”，AI 只标了客服问题，漏了未收到 | v3 加提示：抱怨客服或收到别的商品时，检查是否也没收到货 |
| **本身有争议** | 5 | 120 粒装变 60 粒装：算发错货还是与描述不符？ | 不算模型错误，在规范中列为边界案例 |

- “其他”类别精确率最低，主要原因是发票问题（4 次误报中占 3 次）
- 漏标第二个标签的错误，**人工标注时也犯过同样的错**（第 51 条），说明这类评论本身容易让人忽略次要问题

**关于标准答案的修正：** 第 33 条（“在等店家答复有没有货”）原标为“客服 / 售后”，违反了规范中“正常处理中的不算”的规则，改为“其他”。**只修正违反书面规范的标注**，不因为 AI 的判断不同就修改模糊样本，避免评估结果虚高。

## 5. 产品建议（初步）

1. **延迟预警与主动沟通：** 延迟是差评的首要原因，且差评率随延迟天数上升。可以对预计会延迟的订单提前通知用户并给出补偿，用“延迟订单差评率”衡量效果
2. **卖家发货准确率管理：** 少发和发错货占差评的 27%，属于卖家责任。可以把这两类差评计入卖家评分
3. **差评自动分类分发：** 大模型在 7 个具体类别上的精确率都在 90% 以上，可以把差评自动分给物流、卖家管理、客服等对应团队；“其他”类精确率低，先转人工复核

## 6. 局限与后续

- **样本量小：** 评估集只有 100 条，部分类别（如运输破损）只有 4–5 条，指标会有波动
- **标注者：** 标准答案由一名主要标注者完成，另有一名标注者参与一致性检查和分歧裁决
- **翻译依赖：** 标注借助机器翻译，可能存在理解偏差
- **后续：**
  - prompt v3：加入发票规则和多标签检查提示
  - 另抽 50 条**新样本**作为独立测试集评估 v3。用同一批 100 条既改 prompt 又测试，会造成过拟合
  - 用效果确认后的方案对全部 10,890 条差评分类，得到完整的问题分布
  - 对比不同模型的准确率和成本
